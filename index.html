Chatbot on hundreds of technical manuals

A chatbot for the service desk that answers support questions from several hundred technical manuals and documents, so an operator gets the right procedure without searching for it.

The manuals are split into clearly delimited paragraphs following an internal procedure, which makes retrieval more accurate. Every question is searched twice, by meaning and by keywords, and the passages found go through a final ranking. The answer is detailed and precise, and it is built only from what the manuals say, to avoid hallucinations.

Code knowledge agent

A knowledge base built on the company's codebase: the code is indexed and turned into documentation, so that questions about it can be asked in plain language.

The documentation and the processed code then serve as context, as in a RAG system, to make development work faster: more context for each task, and fewer tokens spent on paid models. Answers also adapt to who is asking and to the type of request, such as an impact analysis or documentation.

Tool-calling orchestration for the ERP

An orchestration layer on top of the ERP: people ask in plain language, and the model picks and calls the tools that read or change the data, without anyone needing to know the tables behind it.

The tools are not hard-coded but discovered at request time, and they cover the everyday operations on tables and business objects: viewing, adding, editing, counting and deleting records. Every deletion asks for a confirmation first.

Self-hosted inference

An NVIDIA DGX Spark on the premises runs all the models, language, embedding and reranking, instead of a cloud API, so internal data stays inside the company network. The language models are from the Qwen family and are served with vLLM and Ollama. All the systems here use it, with cloud models as a fallback.

Research Intern, Deep Learning

University of Padua · MSc thesis, supervised by Prof. Loris Nanni

Thesis: Neural Network Approaches for Classifying Variable Star Light Curves.

  • Reviewed recent work on classifying astronomical time series and built two PyTorch models for Zwicky Transient Facility (ZTF) light curves: a 2D-CNN on image-like representations of the curves and a hybrid CNN-LSTM on the reconstructed sequences.
  • With 5-fold cross-validation, the 2D-CNN reached 99.95% accuracy (F1 0.9995) on the full 5-class dataset, 94.6% on a balanced 5-class subset and 88.7% on 10 classes.
  • The CNN-LSTM reached 90.0% on the full dataset while training about three times faster, which makes it the better option when compute is limited.
